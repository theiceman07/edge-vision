# Data card

## Dataset v1: my own enclosure photos (the IDRP part)
| Item | Value |
|---|---|
| What | Photos of the 3D-printed enclosure for a DC-DC buck converter: lid + base, a GOOD set and a DEFECTIVE set (CAD in `cad/enclosure_*.f3d`) |
| Camera / rig | Logitech Brio 100, 640x480 MJPG, fixed mount above a dark mat, manual focus (`app/focus.txt`), room light; Raspberry Pi 5 |
| How captured | `app/capture_data.py --set enclosure --manual` (one clean snapshot per placement, hands out of frame) |
| Classes | `enclosure_good` (0), `enclosure_defective` (1); empty-mat photos are negatives with no labels |
| Images used | 158 = 60 good + 67 defective + 31 empty (train 111 / val 31 / test 16 = 70/20/10) |
| Images dropped | 26 part photos with hands in the frame (auto-labelling would box the hand); 305 earlier photos with hands are kept aside in `app/mydata_enc_hands/` and NOT used |
| Labels | Auto-generated by thresholding (white parts on a dark mat) in `tools/label_enclosure.py`: one box per connected group of parts, class = folder. Checked by eye on a 30-image sample. |
| Split | Group-aware: photos whose 64-bit dHash is within 6 bits stay in one split; verified by `tools/split.py` (0 identical files, 0 near-duplicate part photos across splits). A first per-photo split leaked and was replaced. |
| Known issues | Touching parts are boxed as one group, so boxes are not always tight; shadowed undersides are sometimes cut off; the test set has only 6 good + 7 defective images, so accuracy will be rough; the two variants look alike at 480 px and may be hard to separate; single camera, single mat, single lighting setup |
| Your changes | n/a (own data) |
| Where | `evidence/M1/04_dataset_v1/dataset/` (images + labels + split.csv + data.yaml) |
| Your training run | Not done yet. A CPU run on the Pi was started on 2026-11-02 and stopped at about epoch 15 (not used, no results kept). Training is planned on Google Colab T4 with `training/train_enclosure_colab.ipynb` and `training/enclosure_dataset.zip`. |
